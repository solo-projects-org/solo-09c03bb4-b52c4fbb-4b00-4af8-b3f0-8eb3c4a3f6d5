# 展馆电子导览 A/B 两轮评估台

Flask + SQLite 实现的电子导览两版试用评估应用，支持缺报推演、唯一可能结论签发与更正失效管理。

## 评估规则

1. 预置 A、B 两组各 40 人的入组名单与顺序（`A001`–`A040`、`B001`–`B040`），编号 1–20 进入首轮。
2. **首轮**：每组前 20 人，双侧 Fisher 精确检验，`p ≤ 0.025`（含等号）时完成率高的一版胜出并停止。
3. **第二轮**：首轮不显著才进行，用每组全部 40 人，同样双侧 Fisher、阈值 0.025；显著则完成率高者胜。
4. 两轮都不显著 → 无胜出（`NONE`）。
5. **缺报推演**：枚举缺报者完成/未完成的所有可能赋值；同一缺报者在两轮中的完成状态强制一致（前 20 名缺报者的取值同时作用于两轮）。
6. 页面为**每种可能结论**列出一组可得到它的两轮分组完成数及精确 p 值（分数 + 小数）。
7. **签发**：仅当按最新底表推演后结论唯一时才允许签发；签发瞬间重新核实。
8. **更正失效**：CSV 更正后若原结论不再是当前唯一可能，所有仍有效的旧签发在同一事务内标记 `INVALIDATED` 并记录原因；失效签发不会被复活。
9. 底表、更正记录、签发状态均存 SQLite；所有写操作单事务提交，任一步失败整体回滚，保留原状。

Fisher 检验为纯标准库实现（`app/stats.py`，`fractions.Fraction` 精确分数），无 scipy 依赖。

## 启动（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

- 数据库位于命名卷 `guide-data`（容器内 `/data/guide.db`），重启不丢数据。
- 单 gunicorn worker + 多线程，避免 SQLite 多进程写竞争。

本地非 Docker 运行：

```bash
pip install -r requirements.txt
export APP_DB=./guide.db
python wsgi.py
```

## CSV 格式

```csv
id,status
A001,1
B018,0
```

- 表头可选；`status` 接受 `1/0`、`yes/no`、`true/false`、`完成/未完成`。
- 整批校验：未知编号、非法状态、文件内编号重复、空文件都会导致**整批拒绝、零写入**。
- 首页可下载当前底表模板 `/roster.csv`。

## 页面分区

1. 底表上报情况（已报完成/未完成、首轮与全员新增缺报数）
2. 缺报推演表（每种可能结论的代表性两轮完成数与精确 p 值）
3. 签发区（唯一可签 / 禁用按钮）
4. CSV 上传
5. 签发记录（有效 / 已失效 + 失效原因与时间）
6. 更正记录
7. 完整底表

## 测试

```bash
python -I tests/test_app.py
```

覆盖：预置名单、缺报改变首轮停止（5/13 显著 p≈0.02484 vs 5/12 不显著 p≈0.05355）、
唯一才可签发、更正致旧签发失效（三种情形）、非法 CSV 整批回滚、两轮状态一致性枚举、
阈值含等号边界、写入失败故障注入回滚。

## 目录

```
app/__init__.py    Flask 路由（上传、签发、失效、核实）
app/db.py          SQLite 建表/预置名单/CSV 解析/事务化写入
app/engine.py      缺报枚举与两轮推演引擎
app/stats.py       双侧 Fisher 精确检验（纯标准库）
app/templates/     单页界面
wsgi.py            入口（含 Fisher 缓存预热）
tests/test_app.py  端到端测试
```
